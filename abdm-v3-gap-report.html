ABDM v3 Gap & Defect Report

NalamDesk (desktop + cloud) — validated against ABDM v3 sandbox docs, the Nirmitee v3 Postman collection, and NHA functional test-case workbooks (M1/M2/M3). M4 (NHCX) out of scope.

Top defects

  1. DEFECT ABHA card fetch uses wrong path+method: GET /v3/profile/account/abha-card vs v3 POST /v3/profile/account/getAbhaCard. Allowlist only permits the GET variant, so the live call is rejected before the vendor token attaches.
  2. DEFECT ABHA enrollment paths do not match v3: service uses enrol/byMobile and enrol/verify; v3 uses enrol/byAbdm. enrol/byAbdm is never called.
  3. DEFECT HIP callback paths are v0.5-era: /api/v3/hip/token/on-generate-token and /api/v3/link/on_carecontext are not in the v3 callback set, so HIP-initiated linking may silently never complete.
  4. GAP Allowlist missing v3 endpoints: /hip/v3/link/patient/links/sms/notify2 (M2) and GET /gateway/v3/bridge/getServices (M2).
  5. GAP HIU uses a non-v3 callback path: /api/v3/hiu/health-information/on-request is not part of the v3 inbound set (likely dead code).
  6. GAP Scan-and-share reply shape and endpoint marked 403 in sandbox (WSO2 issue) — implementation not validated live.
  7. GAP All paths carry "reconfirm against sandbox" TODOs (#152); the mock responder masks path drift.
